section: Bug fixes
- [user] Making and removing an Admin, marking someone returned, issuing a set-password link, importing and removing a link, adding a Contributor by email, and signing in through the company's sign-in (OIDC) now make their checks in the same transaction as their write, so a change that lands at the same moment can no longer slip in between: an Admin removed while they make another Admin, or an Owner who handed off a Goal while removing one of its links, is now refused (#571).
- [user] Setting a password and signing in with one still hash outside the transaction, but now read the link, or the stored password and its lockout, again inside the one that writes: a set-password link used by someone marked Departed meanwhile is refused, and a sign-in checked against a password changed meanwhile is refused rather than let in with the old one (#571).
- [user] Syncing the directory as an Admin checks again, in the transaction that records the people, that the actor is still an Admin (#571).

section: Architecture
- [internal] A write the Service makes outside a transaction now panics, naming the query ("write outside a transaction: SetAccountName"), in production too, where the web server recovers it as a 500: `db.New` is handed `writeOutsideTxGuard` around the database (`internal/domain/txguard.go`), and `WithinTx` binds the queries to the `*sql.Tx` as before. Every write that ran outside one now runs in its own: setting a Name, ending sessions, recording a scheduled run, pruning stale rows (both deletes in one), spending an Undo token, creating an Account, and each email's sent or failed mark (#571).
- [internal] `TestCommandsCheckInsideTheirTransaction` (`internal/domain/txdiscipline_test.go`) reads the domain package with go/ast and fails when an exported command that can reach a write touches the database before its first `WithinTx`. It allows a lookup by email and a hand-over to another command, and exempts, each with its reason, the five Undo restores, `SetPassword`, `PasswordSignIn`, `DeliverEmail`, `PublishReport` and `SyncDirectoryAsAdmin` (#571).
