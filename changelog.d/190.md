section: Breaking changes
- [ops] **Database schema / migrations**: migration `0042_milestone_changes_outside_checkins` runs on startup and is one-way. It rebuilds `milestone_changes` with `checkin_id` nullable, so a Milestone change can be recorded outside a Check-in, and adds a nullable `author_id`. Every existing row is copied with its `id` and columns, and its `author_id` is backfilled from its Check-in's author. A build from before it can't read the rebuilt table, so back the database up before upgrading (#190).

section: New features
- [user] The Owner or a Delegate can add a Milestone from the Goal page at any time while the Goal is Proposed, Active or On Hold, without a Check-in: "+ Add" on the Milestones card opens an Add Milestone form (name, date) in place. A refused add, such as a missing name or date, comes back with the form open, the reason beside it and what you typed still in it. Once the Goal is Active, the addition is its own entry in the Goal's History ("Dana Reyes added Milestone GA (2026-05-01)"), listed under Check-ins, and a Milestone added after the latest Check-in is marked New. An addition while Active counts toward Milestone Churn, and one while On Hold doesn't. Additions while Proposed, including on the define page, still leave no History entry. Moving a Milestone's date and marking it Done or Removed still happen only in a Check-in (#190).

section: Bug fixes
- [user] Only a Goal's Owner or a Delegate can add or edit its Milestones. Until now anyone signed in could add a Milestone to any Goal, even a Done or Cancelled one, or rename one, by posting to `/goals/{id}/milestones` or `/milestones/{id}`. Anyone else is now refused with 403, and adding to a Done or Cancelled Goal is refused (#190).
