section: New features
- [ops] People and their Managers now come from the org's directory: set `GOAL_TRACKER_DIRECTORY_URL` (Authentik's base URL) and `GOAL_TRACKER_DIRECTORY_TOKEN` (an API token that can read users), and the app syncs every user at startup and then hourly. Each person gets an Account if they have none, their Name, and their Manager from the `manager` attribute. No one is ever marked Departed, and someone the directory stops listing keeps their last Manager. A failed sync changes nothing and logs its cause at ERROR. Manager cycles are kept and logged at WARN. Setting only one of the two variables stops startup, naming the missing one. Unset, there's no sync and no one has a Manager (ADR 0008) (#262).
- [user] When the directory sync is configured, the Admin page shows when it last ran and how many people it read, or its error, with a **Sync now** button that runs it at once (#262).
- [ops] The local Authentik in `dev/authentik/` has a service account for the directory sync that can only read users, with a token from a new `.env` value, `GOAL_TRACKER_DIRECTORY_TOKEN`. `make start` passes the directory URL and token to the app, and `check.sh` checks that the token can list users and can't change one (#262).

section: Architecture
- [internal] An Account carries its Manager, and the domain answers who is in a person's Chain and whether anyone is under them (`Service.Chain`, `Service.HasAnyoneUnder`). No page uses them yet. The directory client sits behind `domain.Directory`, so another provider or SCIM can be added without touching the domain. The `testsupport` harness has `SetManager` for arranging Chains in tests (#262).
