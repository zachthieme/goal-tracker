section: Bug fixes
- [user] A person marked Departed can no longer save, edit, curate or publish a Report, change its Report Delegates, raise, close or reassign an Action Item, or comment or reply: each is refused with "a Departed person can't …", and the Report pages offer them none of it (#607).
- [user] Someone who may not reassign an Action Item is now told so ("only the Report's creator, a Report Delegate or its publisher, an Admin, or the creator's Manager reassigns an Action Item") even when the item is already closed, rather than being told it is closed (#607).
- [user] Marking someone Departed or returned names an Account that doesn't exist as "account does not exist" whoever asks, before asking whether they are an Admin (#607).

section: Architecture
- [internal] Each Report and Action Item command's rule for who may make it is one pure function in `internal/domain/reportrules.go`, as Goal commands' are in `goalrules.go`; the command and the Report pages evaluate the same rule, through `Service.ReportPermissions`, `Service.ActionItemPermissions` and `Service.RequireReportEditor`, pinned by a parity test. `CanManageReport`, `CanManageReportDelegates` and `CanReassignActionItem` are gone, `MarkDeparted`, `MarkReturned` and `SyncDirectoryAsAdmin` check Admin once, and `SyncDirectory` no longer takes a check to run in its transaction (#607).
